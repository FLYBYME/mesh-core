Read the issue. It has the full list. What follows is what you cannot learn

INSTALL THE CURRENT KERNEL FIRST

    npm update @flybyme/mesh-web

package.json names v0.15.11. `npm install` alone will serve you a cached git
dep at the old commit and report "up to date" — this has cost hours twice. Check
`node_modules/@flybyme/mesh-web/package.json` says 0.15.11 before you start.

0.15.11 fixed a real defect you would otherwise hit: a collection's default
query was created lazily on first read and inherited whatever reactive scope
happened to be evaluating then — so a console that first read `parts` inside a
computed lost the query's session effect on that computed's next run. Signed-out
lists kept showing the previous user's rows.

WHAT THE ENDPOINTS ACTUALLY LOOK LIKE

They are all in the generated client already, since mesh-serve exposes them. Read
`src/generated/api.ts` for the real input and output types rather than working
from the issue's prose. In particular:

  * `builder.release_repo` returns BOTH `released` and `failed`. Render both.
    Failures are the normal case while a repository is being worked on, and a UI
    that shows only successes is how a half-released repo looks fine.
  * `builder.import_repo` takes an OPTIONAL `ref`. Leave it empty by default —
    absent means the repository's own default branch, and hard-coding `main` is
    a guess about somebody else's repository that was already wrong once.
  * `catalog.declare` replaces `mesh.json`. The declaration form is the point of
    this issue, not a nice-to-have: it is what makes a part editable at all.

THESE CALLS ARE SLOW AND DESTRUCTIVE

`release_repo` clones, bundles and publishes. It takes tens of seconds and it
changes what a hostname will resolve to. So:

  * a button that fires one must show it is running and must not be re-armed
    while it is
  * the kernel has a confirm capability (`cx.confirm`) — use it before anything
    that publishes or deploys

DO NOT ADD REFRESH BUTTONS

Dispatch 12 just removed every one of them. Collections are live or they say so.
After a release completes, the catalog list updates because `partVersion.created`
arrives — not because you called `refetch()`.

DO NOT:
  - widen scope — a second problem gets a NEW issue on FLYBYME/surfdns, signed
    and linked, not a bigger PR. A PR that fixes two things cannot be reverted
    for one of them.
  - delete, skip, or `.only` past a failing test
  - push to master
