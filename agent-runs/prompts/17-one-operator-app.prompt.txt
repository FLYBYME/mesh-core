ROUTER PARAMS — DO THIS, IT IS PART OF THE SAME CHANGE

`src/nav/router.ts` has:

    export interface Route { readonly owner?: string; readonly view: string; }

There are no params. `grep -c params src/nav/router.ts` returns 0. That is
incomplete: the address of a window is `(app, view, params)`, and a URL is only
its serialisation. Without params, "the sites view" is linkable and "site
foo.example.com" is not — and with four views folded into one app, selection is
exactly what a person wants to paste to a colleague.

Add it:

    export interface Route {
        readonly owner?: string;
        readonly view: string;
        readonly params?: Readonly<Record<string, Json>>;
    }

`Json` is serialisable by construction, so a route is serialisable by
construction. Choose the URL encoding, put it in `formatRoute`/`parseRoute`,
and round-trip it in a test: `parseRoute(formatRoute(r))` deep-equals `r` for
every shape you support, including empty params and a param containing `/`.

Then use it: selecting a part, a release, a site or a node puts the selection
in the route, and landing on that URL restores the selection.
