THE TASK

Every console in this repository holds its own array and has a refresh button
beside it. Both are wrong now, and the kernel work that makes them wrong is
already merged — mesh-web 0.15.10, FLYBYME/mesh-web#4:

  * `shouldFetch()` inspects `ApiCall.gate`. A collection behind `user` no
    longer fires before a session exists, so the 401 the catalog was reporting
    as a load failure is gone at the source.
  * A session arriving (absent -> present) reloads any query holding no data.
    Nothing in a console needs to watch for sign-in itself.
  * `CollectionQuery.live` is a `ReadonlySignal<boolean>`. A streamed
    collection applies `created` / `updated` / `deleted` as they arrive and
    resyncs on reconnect.

Install it first — this worktree's package.json may still name an older tag —
and read `node_modules/@flybyme/mesh-web/dist/models/types.d.ts` for the real
surface rather than working from this description.

WHAT TO CHANGE, in catalog, releases, fleet and sites:

  1. Delete every refresh button and every hand-rolled `refetch()` on a timer
     or a click. A list that can follow must follow. If a particular collection
     genuinely cannot stream, it says so in the UI — it does not get a button
     back.

  2. "Not signed in" is a state, not an error. The catalog currently renders a
     failed request where the honest answer is that auth has not published a
     session yet. That was the complaint that opened this issue:

         the catalog browser has no understanding that the auth extention is
         logged in

  3. Surface `live`. A list that is following says so; a stream that has
     dropped is visible rather than silently stale. Small and quiet — this is
     an indicator, not a banner.

WHAT YOU CANNOT ASSUME:

`live` is `false` today for every collection, because the generated client does
not declare its events yet. That is FLYBYME/surfdns#57, running in parallel in
mesh-serve, and it lands separately. **A collection reporting `live: false`
must still load and still work.** Do not fake the stream, do not poll to
simulate it, and do not block on #57.

Browser tests are the evidence here: a console that renders correctly with no
session, then renders rows when one arrives, is exactly the regression that
keeps coming back.
